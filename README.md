# 수업상점 · 작은 성취를 차곡차곡

교과전담 교사가 여러 반의 수업 과제를 확인하고, 학생이 적립한 포인트로 작은 보상을 구매하는 Firebase 기반 웹앱입니다. 교사별로 ‘○○ 선생님의 ○○상점’을 개설합니다.

## 기능

- 교사 Google 로그인, 학년별 학급 개설, 학급 가입 코드·링크 공유
- 학생의 이름·비밀번호 직접 등록, 교사 승인·반려, 모둠·모둠장 지정
- 학년 + 개인 코드(알파벳 2자리·숫자 4자리) + 비밀번호 로그인
- 교사의 비밀번호 초기화·새 코드 발급, 학생의 본인 비밀번호 변경
- 과제 등록, 교사 또는 해당 모둠장의 수행 확인, 포인트 적립·확인 취소
- 과제 보상·상품 가격 슬라이더, 숫자 직접 입력과 선택값 미리보기
- 상품 가격·재고·진열 관리, 학생 구매, 교사 보상 지급·취소 및 환급
- 학생별 포인트 원장, 학급 요약, CSV 내보내기
- 로그인 없이 조작 가능한 가상 학급 체험. 실제 Firebase 기록과 분리
- 토끼 상점과 상품은 생성한 PNG 이미지. 상점 이름과 수치는 실제 글자

## 개발

Node.js 24와 npm을 사용합니다.

```text
npm ci --ignore-scripts
npm run build
npm run dev
```

로컬 주소: http://127.0.0.1:8842/

```text
npm test
npm run test:rules
```

규칙 검사는 Java 21 이상과 Firebase Firestore Emulator가 필요합니다. 운영 프로젝트에 테스트 자료를 넣지 않습니다. 배포 대상은 `dist/`뿐입니다. Firebase SDK는 브라우저용으로 번들되며 서버 비밀키를 사용하지 않습니다.

## Firebase

프로젝트 ID: `class-shop-f0f24`. 클라이언트 설정은 `src/config.mjs`에 있습니다. 이 웹 설정은 공개 식별 정보이며 관리자 자격 증명이 아닙니다.

Authentication: Google(교사), 이메일/비밀번호 제공업체(학생). 학생의 실제 이메일은 받지 않고 내부 계정 식별자를 사용합니다. 비밀번호는 Firebase Authentication에만 전달하며 Firestore, CSV, 입장 카드, URL에는 저장하지 않습니다. 교사는 비밀번호를 조회하거나 대신 지정하지 않습니다. 초기화 시 기존 코드와 UID 연결을 해제하고 새 개인 코드를 발급합니다. 학생이 새 비밀번호를 설정하고 교사가 재승인하면 기존 포인트·과제·구매 기록으로 다시 연결됩니다.

교사는 학급만 개설해 가입 코드를 공유합니다. 학생은 학년·학급 가입 코드·이름·본인 비밀번호로 신청하고 별도의 개인 코드를 받습니다. 교사 승인 전에는 상점의 명단·과제·상품·포인트에 접근할 수 없습니다. 승인 후 로그인에는 학년·개인 코드·비밀번호를 사용합니다. 동명이인은 서로 다른 개인 코드로 구분합니다. 학급 가입 코드를 교체해도 이미 가입한 학생의 개인 코드는 유지됩니다.

기존 코드 전용 학급은 교사가 상점을 처음 열 때 새 구조로 전환합니다. 학급 이름에서 학년을 확인할 수 없는 경우 교사가 학년을 먼저 설정합니다. 기존 학생의 포인트와 수행 기록은 보존하고 이전 익명 접근은 해제합니다. 해당 학생은 새 개인 코드로 ‘선생님이 비밀번호를 초기화했어요’를 선택해 비밀번호를 설정하고 재승인을 받습니다.

규칙: `firestore.rules`. 기본 거부, 교사 상점 소유권, 학생 본인, 교사가 허용한 모둠장 범위를 검사합니다. 역할과 잔액을 클라이언트 화면의 숨김에 의존하지 않습니다. 수행 확인·구매·환급은 `runTransaction`과 `getAfter()` 보안 검증으로 원장·잔액·재고·상태가 함께 바뀌어야만 허용합니다. 원장은 수정·삭제할 수 없습니다.

참고: 모둠장은 같은 모둠 학생의 이름·잔액·수행 상태를 볼 수 있습니다. 초대 목록과 구매 원장은 볼 수 없습니다. 이름 대신 교사와 정한 별명을 사용할 수 있습니다. 6자리 코드는 식별자이므로 비밀번호와 교사 승인이 접근 권한을 결정합니다. 코드별 공개 조회 문서에는 라우팅 식별자만 들어가며 이름·비밀번호·명단·성적은 포함하지 않습니다. 코드 목록 조회는 차단합니다. 공유 링크는 코드를 URL fragment에 담고 입장 완료 후 제거합니다. 교사·학생 모두 브라우저 세션 인증을 사용하며 공용 기기에서는 로그아웃해야 합니다.

운영 보안 설정과 검증 결과는 [보안 기록](docs/security.md), 제출 초안은 [과제 제출 자료](docs/submission.md)를 확인하세요.

## 배포

GitHub Pages는 `.github/workflows/pages.yml`을 사용합니다. 저장소 Settings → Pages → Source: GitHub Actions로 설정합니다. `main` 업로드 시 기본 검사·빌드 후 `dist/`를 배포합니다. 규칙 배포는 이 워크플로에 포함하지 않으며 Firebase 콘솔 또는 인증된 Firebase CLI에서 별도로 적용합니다.

현재 Firebase 인증 승인 도메인에 `ajootree.github.io`를 등록하고, 웹 API 키의 HTTP 리퍼러를 `https://ajootree.github.io/*`, `https://class-shop-f0f24.firebaseapp.com/*`, `http://127.0.0.1:8842/*`로 제한했습니다. GitHub Pages의 cross-origin 요청은 경로가 생략될 수 있어 배포 도메인 단위로 허용합니다. 이 제한은 데이터 접근 권한을 대체하지 않으며 Firestore 규칙을 함께 적용했습니다. 허용 주소 200·미등록 주소 403 응답을 확인했습니다. 다른 개발 주소를 사용할 때는 해당 주소를 허용하거나 로컬 에뮬레이터로 검사합니다.

과제 필수 조건별 구현 내용과 시연 순서는 [과제 조건 점검](docs/assignment-checklist.md)을 확인하세요.
