# 과제 조건 점검

작품: 수업상점

배포 주소: https://ajootree.github.io/little-class-shop/

저장소: https://github.com/ajootree/little-class-shop

## 필수 조건과 구현 내용

| 과제 조건 | 구현 내용 | 확인 방법 |
| --- | --- | --- |
| 로그인 없이 웹앱 접속 | 첫 화면과 가상 학급 체험 공개 | 배포 주소에서 ‘가입 없이 먼저 둘러보기’ 선택 |
| 입력·버튼 등에 반응하는 상호작용 | 이름·과제 입력, 학년·학급 선택, 수행 확인 버튼, 모둠장 권한 체크박스, 과제 보상·상품 가격 슬라이더 | 체험 교사 화면에서 과제 추가·상품 수정 및 수행 확인 |
| Firebase DB 연동 | 학급·학생·가입 승인·과제·수행·포인트·상품·구매 내역을 Firestore에 저장 | 실제 교사·승인 학생 로그인 후 기록 저장·새로고침 확인 |

| DB 쓰기 보안 | 승인 전 접근 차단, 학생의 직접 잔액·역할 수정 차단, 중복 적립·품절·잔액 부족·위조 구매 거부 | Firestore 에뮬레이터 규칙·거래 검사 |

| 실제 배포 주소 허용 | API 키 리퍼러에 `https://ajootree.github.io/*`, Firebase 인증 승인 도메인에 `ajootree.github.io` 등록 | 실제 공개 주소의 접속과 Firebase 요청 확인 |

| 개발 의도·사용 프롬프트 제출 | 개발 의도와 실제 프롬프트 발췌 정리. 별도 개발 기록 시트 보관 | `docs/submission.md`와 사용자가 정리한 제출 기록 확인 |

과제 안내의 ‘입력, 버튼, 슬라이더 등’은 상호작용 예시입니다. 앱에는 세 가지를 모두 제공하며, 슬라이더는 과제 보상과 상품 가격을 정하는 실제 기능에 사용합니다.

## 슬라이더의 동작

- 과제 완료 보상: 1~1,000포인트. 기본값은 10이며 막대를 움직일 때 10포인트씩 바뀌고 숫자 입력과 현재 선택값이 함께 바뀝니다.
- 상품 가격: 1~10,000포인트. 막대는 10포인트 단위로 움직이며 숫자 직접 입력도 지원합니다. 기존 5·15포인트 같은 값은 보존하고 해당 값에서 10씩 조절합니다.
- 등록·저장 버튼을 누르기 전에는 실제 기록이 바뀌지 않습니다. 저장한 값은 기존 포인트·구매 검증 규칙을 적용받습니다.

## 보안 설정 확인

2026-11-14 Google Cloud의 기존 Firebase Browser key에 웹사이트 제한을 저장했습니다. 기존 API 25개 제한은 유지했습니다.

- `https://ajootree.github.io/*`: 실제 배포 사이트
- `https://class-shop-f0f24.firebaseapp.com/*`: Firebase 로그인 처리
- `http://127.0.0.1:8842/*`: 지정 로컬 개발 서버

읽기 전용 Firebase 인증 설정 요청으로 실제 배포 주소에서 HTTP 200, 미등록 주소에서 HTTP 403 및 `API_KEY_HTTP_REFERRER_BLOCKED`를 확인했습니다. 이 주소 제한은 Firestore의 계정별 접근 권한을 대체하지 않으며 두 설정을 함께 적용했습니다.

## 시연 순서

1. 공개 주소에서 체험 시작 → 과제 추가 → 보상 슬라이더와 직접 입력 조절 → 과제 등록.
2. 학생 수행 확인 → 적립 확인 → 학생 역할로 전환 → 상품 구매와 잔액 변화 확인.
3. 실제 교사 화면에서 학급 가입 링크 공유 → 학생 직접 가입 → 교사 승인 → 학급 가입 코드·내 이름·비밀번호 로그인 → 로그인 정보 저장·자동 로그인 확인.
4. 실제 계정의 과제·포인트·구매 기록을 새로고침 후 다시 확인.

체험은 실제 학생 자료와 분리된 브라우저 세션 저장을 사용합니다. Firebase DB 저장 시연은 실제 로그인 화면에서 진행합니다. 체험 저장을 DB 저장의 증거로 제시하지 않습니다.

## 검증 범위

자동 검사 41개(기본 8개·로그인 저장 2개·DB 권한 16개·실제 SDK 인증 통합 15개) 통과. 브라우저에서는 보상·가격 슬라이더의 10단위 이동과 숫자 입력 동기화, 세 항목 가입·이름 로그인·교사 승인·자동 로그인·코드 및 이름 복원을 확인했습니다. 실제 모바일 기기 검수는 별도이며, 개발 의도와 실제 제출할 프롬프트 기록은 사용자가 최종 확인합니다.
