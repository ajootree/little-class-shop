# 학생 직접 가입·교사 승인

## 사용 순서

1. 교사는 상점에서 학년을 선택해 학급을 만듭니다. 학급 이름은 교사 관리용이며 학생 로그인에는 입력하지 않습니다.
2. ‘학급과 모둠 → 학급 가입 초대’에서 학년과 학급 가입 코드 또는 가입 링크를 공유합니다.
3. 학생은 가입 화면에서 이름 또는 교사와 정한 별명, 본인 비밀번호를 입력합니다. 비밀번호는 12~128자이며 긴 문장도 가능합니다.
4. 신청 완료 화면에 나온 개인 코드를 적어 둡니다. 학급 가입 코드와 개인 코드는 모두 `AB1234` 형식이지만 용도가 다릅니다.
5. 교사는 ‘학급과 모둠’에서 신청한 학생을 확인하고 승인합니다. 승인 전에는 상점 기록을 읽거나 포인트를 사용할 수 없습니다.
6. 학생은 ‘승인 확인하고 들어가기’를 누릅니다. 다음부터는 기본 링크의 학생 로그인에서 학년·개인 코드·비밀번호를 입력합니다.

## 비밀번호와 코드 관리

- 학생 본인: 로그인 후 ‘내 비밀번호 바꾸기’. 현재 비밀번호를 확인한 다음 변경합니다.
- 교사: ‘학급과 모둠 → 해당 학생의 코드·비밀번호’. 개인 코드와 설정·승인 상태만 확인할 수 있습니다. 비밀번호 값은 조회할 수 없습니다.
- 분실: 교사가 ‘비밀번호 초기화·새 코드 발급’을 실행하고 새 코드를 본인에게 전달합니다. 학생은 로그인 화면의 ‘선생님이 비밀번호를 초기화했어요’에서 새 비밀번호를 만들고 교사 재승인을 받습니다.
- 초기화와 재승인은 학생 이름·포인트·과제·구매 기록을 삭제하지 않습니다. 이전 코드와 계정의 기록 접근은 해제됩니다.
- 학급 가입 코드 유출: 초대 화면에서 가입 코드를 교체합니다. 기존 학생의 개인 로그인과 접수된 신청은 유지됩니다.
- 같은 이름의 학생: 자동으로 합치지 않습니다. 교사가 실제 학생을 확인해 각각 승인하거나 잘못된 신청을 반려합니다.

## 기존 버전에서 전환

기존 상점은 교사가 한 번 열면 학급과 학생 코드를 새 형식으로 준비합니다. 이름에서 학년을 확인할 수 없는 학급에는 ‘학년 설정’이 표시됩니다. 예전 32자리 코드와 익명 입장 대신 새 개인 코드와 본인 비밀번호를 사용합니다. 기존 학생은 비밀번호 초기화 후와 같은 재설정·승인 절차를 거치며 저장된 기록은 보존됩니다.

## 검증

- 기본 기능 8개, DB 보안 규칙 16개, 실제 SDK 가입·인증 통합 10개: 총 34개 검사 통과
- 로컬 브라우저: 교사 로그인, 가입 코드 공유, 학생 직접 신청, 개인 코드 발급, 교사 승인, 학생 입장, 새로고침 후 세션 복원 확인
- Firebase 운영 설정: 이메일/비밀번호 로그인 활성화, 비밀번호 12~128자 필수 정책 적용
- API 키 HTTP 리퍼러 제한은 2026-11-14 추가 적용했습니다. 현재 설정과 확인 결과는 `docs/assignment-checklist.md`에 정리했습니다.
