# 학생 직접 가입·이름 로그인

## 사용 순서

1. 교사는 학년과 학급을 설정하고 ‘학급과 모둠 → 학급 가입 초대’의 코드 또는 링크를 공유합니다. 학년은 교사 관리에만 사용합니다.
2. 학생은 **학급 가입 코드·내 이름·정한 비밀번호** 세 가지만 입력해 신청합니다. 학급 코드는 알파벳 두 자리와 숫자 네 자리이며 비밀번호는 12~128자입니다.
3. 교사는 실제 학생인지 확인하여 승인하거나 반려합니다. 승인 전에는 명단·과제·상품·포인트에 접근할 수 없습니다.
4. 학생은 ‘승인 확인하고 들어가기’를 선택합니다. 다음부터는 학생 로그인에서 **학급 가입 코드·내 이름·비밀번호**를 입력합니다. 개인 코드는 기억할 필요가 없습니다.

## 로그인 저장

- ‘로그인 정보 저장’: 이 브라우저에 학급 코드와 이름만 저장해 다음 로그인 때 채웁니다. 비밀번호는 저장하지 않습니다.
- ‘자동 로그인’: Firebase 인증 상태를 이 브라우저에 유지하여 새 탭이나 브라우저 재시작 후에도 입장합니다. 기본값은 꺼짐이며 공용 기기에서는 선택하지 않습니다.
- 자동 로그인 없이도 같은 탭에서는 새로고침 후 인증을 유지합니다. 로그아웃하면 인증 상태와 자동 입장 정보를 지웁니다. 선택해 둔 코드·이름 자동 채움은 유지합니다.

## 이름과 비밀번호 관리

- 같은 학급의 로그인 이름은 중복할 수 없습니다. 공백과 영문 대소문자는 로그인 구분에 사용하지 않습니다. 동명이인은 교사와 상의하여 이름 뒤에 번호 등을 붙입니다. 다른 학급에서는 같은 이름을 사용할 수 있습니다.
- 교사는 학생 ‘설정’에서 로그인 이름을 수정하고 모둠·모둠장·사용 허용을 관리합니다. 이름을 바꾸면 학생에게 알려 줍니다.
- ‘로그인 관리’에서는 학급 코드·이름·설정 및 승인 상태와 로그인 링크를 확인합니다. 교사와 다른 학생은 비밀번호를 조회할 수 없습니다.
- 학생 본인은 ‘내 비밀번호 바꾸기’에서 현재 비밀번호를 확인한 뒤 변경합니다.
- 분실 시 교사가 ‘비밀번호 초기화’를 실행합니다. 학생은 ‘선생님이 비밀번호를 초기화했어요’에서 **같은 학급 코드·이름**과 새 비밀번호를 입력하고 재승인을 받습니다. 기존 포인트·수행·구매 기록은 유지합니다.
- 학급 코드를 교체하면 이전 코드로 신규 신청을 받지 않습니다. 기존 학생과 접수된 신청은 유지합니다. 새 안내에는 현재 코드를 사용합니다.

## 기존 자료 전환과 검증

기존 상점은 교사가 열 때 학급 코드·이름 로그인 연결을 준비합니다. 이미 비밀번호와 승인이 있는 학생의 인증 연결과 기록은 보존합니다. 오래된 코드 전용 학생은 비밀번호 재설정·재승인이 필요합니다. 기존 동명이인은 교사 화면의 안내에 따라 로그인 이름을 구분합니다.

자동 검사 41개(기본 8개·로그인 저장 2개·DB 규칙 16개·가입 및 인증 통합 15개)를 통과했습니다. 승인 전 접근 차단, 같은 학급 중복 이름 거부, 학급별 이름 구분, 이름 로그인·변경, 초기화·재승인 후 기록 보존, 공개 연결 변조 거부를 확인합니다.

운영 Firebase 비밀번호 정책은 12~128자 필수이며 API 키 HTTP 리퍼러 제한을 적용했습니다. 현재 설정은 [과제 조건 점검](assignment-checklist.md)에 정리했습니다.

로컬 브라우저에서는 세 입력칸 가입, 승인 후 학생 입장, 새 탭 자동 로그인, 로그아웃 후 코드·이름만 복원되고 비밀번호는 비어 있는 상태, 이름 로그인, 자동 로그인 해제 후 새 탭의 로그인 요구를 확인했습니다. 이 검증은 운영 자료와 분리된 에뮬레이터에서 진행했습니다.
