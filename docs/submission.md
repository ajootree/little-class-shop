# 과제 제출 자료 초안

## 작품명

수업상점 — 교과전담 교사의 과제 확인·포인트·보상 웹앱

## 개발 의도

여러 학급을 담당하는 교과전담 교사가 학생의 수업 과제 수행을 간편하게 확인하고, 수행 기록에 따른 포인트 적립과 보상 교환을 운영하도록 개발하였다. 교사는 자신의 이름과 상점 이름을 정하고 학년별 학급 가입 링크를 공유한다. 학생이 이름과 본인 비밀번호를 입력하여 직접 신청하면 교사가 실제 학생을 확인하고 승인한다. 가입과 로그인 모두 학급 가입 코드·내 이름·비밀번호 세 항목으로 통일하여 별도의 개인 코드를 기억할 필요를 줄였다. 실험관찰 작성이나 실험 도구 정리 등의 과제를 등록하고 직접 확인하거나, 특정 과제에서만 모둠장에게 확인 권한을 부여할 수 있다. 학생은 자신의 포인트와 적립 사유를 확인하고 상점의 보상을 구매한다. 교사는 지급 대기 주문과 과제 수행 기록을 통해 수업 운영 현황을 파악한다.

Firebase Authentication과 Firestore로 사용자와 기록을 관리하며, 교사는 자신의 상점, 학생은 본인, 모둠장은 교사가 허용한 같은 모둠 범위에 접근하도록 보안 규칙을 설계하였다. 과제 중복 적립, 잔액 부족 구매, 품절 상품 구매와 원장 변조를 데이터베이스 규칙으로 차단한다.

교사는 과제 보상과 상품 가격을 10포인트 단위 슬라이더 또는 숫자 입력으로 조절하고 선택한 값을 즉시 확인한다. 학생은 과제 수행 확인에 따라 포인트를 적립하고 보상을 구매하며, 화면의 잔액과 구매 상태가 함께 바뀐다. 교사와 승인 학생의 실제 기록은 Firebase DB에 저장하고, 로그인 없이 기능을 살펴보는 가상 체험은 실제 학생 자료와 분리하였다. API 키에는 HTTP 리퍼러 제한과 실제 배포 주소 허용을 적용하였다.

## 실제 사용한 프롬프트 발췌

아래는 사용자가 실제 대화에서 입력한 문장이다. 최초 질문부터 모든 기록을 재현한 문서는 아니며 설계·디자인·구현 단계의 대표 요청을 발췌했다.

1. 기획: “아예 새로 만들어서 파이어베이스에서 쓸게. 그리고 00선생님의 00상점으로 만들 수 있도록 해서. 선생님이 개설하고 학생들에게 링크 공유하는 느낌으로 교담선생님의 포인트제도 느낌으로 가고 싶어.”
2. 권한과 기능: “수업에서 해야할 과제(실험관찰 쓰기라든지)이런게 있으면 교사가 확인하고 체크하거나 아니면 모둠장에게 권한을 주거나. 해서 과제수행하면 포인트 쌓이고 그걸로 상점에서 구입할수 있고 그런식으로”
3. 디자인 탐색: “응 디자인시안 보여줘”
4. 분위기 수정: “아..좀 아기자기한 느낌 업쇼을까”
5. 그림 제작 방식 확인: “아 굿굿 근데 또 css로 도형만드네.. 시안이라 그런거지”
6. 구현 요청: “응 바로 작업 들어가줘. 파이어베이스 연동하고, 보안 신경써서”

## 수정 과정

- 최초 관리 화면 시안에서 파스텔·문구점 분위기로 변경했다.
- 도형으로 표현한 토끼와 상품은 실제 생성 PNG로 제작하고, 수정 가능한 상점 이름과 수치는 실제 글자로 분리했다.
- 모둠장 권한을 과제별·같은 모둠·타인 확인으로 제한했다.
- 과제 수행, 잔액, 주문과 재고가 서로 다른 상태로 저장되지 않도록 트랜잭션과 보안 규칙을 함께 설계했다.
- 로그인 없는 평가용 체험은 가상 자료만 사용하고 실제 학생 자료와 분리했다.
- 학생이 직접 가입하고 교사가 승인하는 방식으로 개선했다. 학생 비밀번호는 Firebase 인증에서 관리하며 교사는 조회할 수 없고 초기화와 재승인만 수행한다.

## 제출 전 확인

- GitHub Pages 공개 주소에서 로그인 없이 체험 가능
- 실제 교사 로그인·과제 등록·학급 코드·이름 로그인·적립·구매·새로고침 저장 확인
- Firestore 규칙 게시, 교사/학생/모둠장 권한 검사
- HTTP 리퍼러 제한·실제 배포 주소 허용 적용, 허용 주소 200·미등록 주소 403 확인
- 위 완료 여부는 실제 확인 후 체크하여 제출한다.

현재 구현 내용과 검증 범위는 [과제 조건 점검](assignment-checklist.md)에 정리하였다.
