# 보안 설계와 검증 기록

## 접근 권한

| 사용자 | 허용 범위 |
| --- | --- |
| 비로그인 | 공개 상점 정보·가상 체험, 정확한 코드에 해당하는 라우팅 정보. 명단·이름·포인트·신청 내용 접근 불가 |
| 교사 | Google 인증 후 본인 상점의 학급·학생·과제·상품·원장 |
| 승인 대기 학생 | Firebase 비밀번호 인증 후 본인 가입 신청 상태만 확인 |
| 승인된 학생 | 비밀번호 인증과 교사 승인으로 연결된 본인 문서·과제·원장·주문, 활성 상품 |
| 모둠장 | 위 범위와 함께 같은 모둠의 명단·잔액·수행 상태, 교사가 허용한 과제의 타인 확인 |

학생과 모둠장은 권한, 재고, 가격, 포인트를 직접 수정할 수 없습니다. 모둠장은 자기 확인·타 모둠 확인·교사 전용 과제 확인·기존 확인 취소를 할 수 없습니다.

## 포인트와 재고

모든 포인트 변경에는 새 원장 이벤트가 필요합니다. 원장에는 변경 사유와 수행자가 기록되며 수정·삭제를 거부합니다. 잔액 단독 갱신이나 예전 원장 재사용은 불가합니다.

수행 확인: 과제·학생 조합에 고정된 체크 문서로 중복 적립을 거부합니다. 확인 취소는 교사만 할 수 있으며 이미 사용한 포인트로 잔액이 음수가 되면 거부합니다.

구매: 상품 가격에 맞는 차감, 재고 1개 감소, 새 주문, 새 원장이 같은 트랜잭션에서 일어나야 합니다. 재고 0개·잔액 부족은 DB에서 거부합니다. 환급은 지급 대기 주문을 한 번 취소할 때 포인트와 재고를 함께 복원해야 합니다.

## 학생 직접 가입과 비밀번호

학생은 학급 가입 코드·내 이름·비밀번호로 가입하고 로그인합니다. 학급 코드는 알파벳 두 자리와 숫자 네 자리이며 전역 충돌 확인과 생성을 Firestore 트랜잭션으로 처리합니다. 학년은 교사가 관리하며 학생 로그인에는 입력하지 않습니다. 내부 연결용 식별자는 화면에서 외울 필요가 없습니다. 학급 코드와 이름은 인증 비밀이 아니며 비밀번호 인증·교사 승인·계정 연결을 모두 통과해야 기록에 접근합니다.

가입자는 본인 이름·비밀번호를 직접 입력합니다. Firebase Authentication 계정 생성과 가입 신청만으로는 학생 명단, 과제, 상품, 포인트·구매에 접근할 수 없습니다. 교사의 승인 트랜잭션에서만 학생 문서와 UID 바인딩, 승인 상태가 함께 확정됩니다. 신청자가 자기 승인, 바인딩 작성, 기존 학생 UID 교체를 수행하는 경로는 없습니다. 같은 학급의 중복 로그인 이름은 가입 트랜잭션에서 거부합니다. 이름은 NFKC 정규화, 공백 제거, 소문자 변환 후 학급 ID와 함께 SHA-256 조회 키를 만들고 규칙에서도 검증합니다. 이 조회 키는 비밀번호 해시나 인증 수단이 아닙니다. 교사의 이름 변경은 기존 연결 해제와 새 연결 저장을 함께 처리합니다. 학급 가입 코드 교체로 이전 코드의 신규 신청을 중단할 수 있습니다.

학생 실제 이메일은 수집하지 않습니다. 128비트 난수에 기반한 내부 계정 식별자를 Firebase 이메일/비밀번호 제공업체에 사용합니다. 비밀번호는 Authentication SDK에만 전달하며 데이터베이스·입장 카드·CSV·URL에 저장하지 않습니다. 보안 규칙은 학생 문서와 신청 문서에 비밀번호·해시 등 임의 필드를 넣는 요청도 거부합니다. 교사 화면에는 설정·승인 여부만 표시합니다. 운영 Firebase의 비밀번호 정책은 필수 시행, 최소 12자·최대 128자로 설정했습니다.

학생의 비밀번호 변경에는 현재 비밀번호 재인증이 필요합니다. 교사 초기화는 기존 초대를 폐기하고 학생 UID를 해제해 기존 계정의 DB 접근을 즉시 차단합니다. 새 내부 인증 식별자로 바꾸고, 학생이 같은 학급 코드·이름으로 새 비밀번호를 만들고 재승인받으면 같은 학생 문서에 연결합니다. 기존 포인트·수행·구매 기록은 유지됩니다. 기존 Authentication 계정은 기록에 접근할 수 없는 상태로 남으며 앱이 관리자 자격 증명을 보유하거나 인증 계정 전체를 조회하지 않습니다.

공개 라우팅 컬렉션은 단건 조회만 허용하며 학생 이름·비밀번호·신청 내용은 포함하지 않습니다. 코드의 전체 목록 조회는 차단합니다. Firebase의 가입·로그인 제한을 사용하지만, 앱이 전용 서버의 IP별 가입 제한이나 CAPTCHA를 추가 구현한 것은 아닙니다. 학급 코드가 유출되어 불필요한 신청이 들어오면 교사가 코드를 교체하고 반려합니다. 실제 학생 확인은 교사의 승인 절차에서 수행합니다.

## 브라우저와 입력

- 사용자 입력 HTML escape, 동적 HTML에 실행 가능한 입력 삽입 금지
- Content Security Policy, 관리자 비밀키 없음
- 내부 인증 식별자는 128비트 난수, 초대·신청 목록은 해당 교사만 조회
- 학급 코드·필요한 경우 이름을 URL fragment로 전달하고 입장 후 제거. 링크에 비밀번호 미포함
- 비밀번호 초기화 시 이전 인증 연결 해제, 재승인 전 접근 차단
- 기본 session persistence, 선택형 자동 로그인은 Firebase local persistence 사용
- 로그인 정보 저장은 코드·이름만 허용하며 비밀번호를 앱 저장소에 쓰지 않음
- 로그아웃 시 인증과 자동 입장 정보 제거, 다른 탭에서 인증이 바뀌면 이전 계정 화면 해제
- CSV 셀의 수식 접두어 방어
- Analytics/Gemini 부가 기능 사용 안 함, 학생 이메일·전화·사진 수집 안 함

## API 키의 HTTP 리퍼러 제한

2026-11-14 기존 Firebase Browser key에 웹사이트 제한을 저장했습니다. 허용 목록은 `https://ajootree.github.io/*`, `https://class-shop-f0f24.firebaseapp.com/*`, `http://127.0.0.1:8842/*`입니다. 기존 API 25개 제한은 유지했습니다. 실제 배포 주소의 읽기 전용 Firebase 인증 설정 요청은 HTTP 200, 미등록 주소는 HTTP 403 `API_KEY_HTTP_REFERRER_BLOCKED`로 응답하는 것을 확인했습니다. 이 작업에서 약관을 대신 수락하거나 결제·요금제 설정을 변경하지 않았습니다.
